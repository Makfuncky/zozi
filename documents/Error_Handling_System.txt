### 🏗️ 2. The Open-Source Observability Stack (What to Install)
To maintain your philosophy of "owning the system" without paying for SaaS vendors like Datadog or New Relic, we will deploy the **LGTM Stack** (Loki, Grafana, Tempo, Mimir/Prometheus) + **Self-Hosted Sentry**. All of these are free and run via Docker.

1. **Grafana Loki & Promtail (Log Aggregation):** 
   * *Promtail* sits on your servers, reads the FastAPI and Nginx log files, and ships them to *Loki*. Loki indexes them by labels (e.g., `app=backend`, `env=production`, `country=OM`) rather than full-text, making it incredibly cheap and fast to host.
2. **Prometheus & Grafana (Metrics & Dashboards):** 
   * *Prometheus* scrapes metrics from FastAPI (via `prometheus-fastapi-instrumentator`) and PostgreSQL. *Grafana* visualizes this data (e.g., "Orders per minute", "Database latency").
3. **Self-Hosted Sentry (Error Tracking):** 
   * Sentry is open-source. You can host it on your own infrastructure via Docker. It captures frontend React crashes and backend Python exceptions, groups them by fingerprint, and shows you the exact line of code that failed.
4. **OpenTelemetry (Distributed Tracing):** 
   * Injects a single `trace_id` that follows a request from the Next.js Frontend $\rightarrow$ Nginx $\rightarrow$ FastAPI $\rightarrow$ PostgreSQL $\rightarrow$ Redis. If a checkout fails, you can see the exact millisecond the database locked up.

### 🗺️ 3. Step-by-Step Implementation Plan

#### Phase 1: Backend Structured Logging (The Foundation)
Standard text logs are unreadable by machines. We must convert all backend logs to JSON.
* **Action:** Replace the standard `logging` setup with `structlog`.
* **The Enrichment Pipeline:** Every log line must automatically include:
  * `request_id` (Already partially built via your `_RequestIdLogFilter`).
  * `user_id` and `country_code` (Extracted from the JWT middleware).
  * `db_query_time_ms` (Intercepted via SQLAlchemy events).
* **Result:** A single log line looks like: `{"level": "error", "request_id": "abc-123", "user_id": 45, "country": "OM", "db_time_ms": 450, "error": "IntegrityError"}`.

#### Phase 2: Frontend Error Telemetry & Source Maps
When a minified Next.js or React Native app crashes in production, the stack trace is useless (e.g., `Error at main.js:1:4592`).
* **Action:** Install the `@sentry/nextjs` and `@sentry/react-native` SDKs.
* **Source Map Upload:** Add a step to your CI/CD pipeline (GitHub Actions) that automatically uploads Webpack/Vite source maps to your Self-Hosted Sentry server upon deployment.
* **User Context:** Configure the SDK to automatically attach the `user_id`, `country_code`, and `device_fingerprint` to every crash report.
* **Result:** When a customer in Saudi Arabia experiences a blank checkout screen, Sentry tells you exactly which React component failed, on which browser, and provides the un-minified code line.

#### Phase 3: Deploying the Aggregation Pipeline (Docker)
* **Action:** Create a `docker-compose.monitoring.yml` file containing:
  * `promtail` (configured to scrape `/var/log/nginx/*.log` and Docker container stdout).
  * `loki` (the database for logs).
  * `prometheus` (scraping FastAPI `/metrics` endpoint).
  * `grafana` (the UI dashboard).
* **Correlation:** Configure Grafana so that when you look at a spike in "500 Internal Server Errors" on a Prometheus chart, you can click the spike and instantly jump to the exact Loki logs for that `request_id`.

#### Phase 4: Distributed Tracing (The "X-Ray" Vision)
* **Action:** Install the `opentelemetry-instrumentation-fastapi` and `opentelemetry-instrumentation-sqlalchemy` packages.
* **Header Propagation:** Ensure your Next.js frontend generates a `traceparent` header and passes it to the FastAPI backend. 
* **Result:** In Grafana Tempo, you can view a waterfall chart of a single user's checkout process, seeing exactly how long the Payment Gateway webhook took vs. the Treasury Ledger database lock.

#### Phase 5: Automated Alerting & Incident Response
Logs are useless if no one is looking at them. The system must wake you up when it's bleeding.
* **Action:** Configure **Grafana Alerting** and **Sentry Alerts** to trigger webhooks.
* **The Alert Matrix:**
  * *P1 (Critical):* "Database connection pool exhausted" or "Payment Gateway Webhook failure rate > 5%". $\rightarrow$ **Action:** Auto-pages the CTO/DevOps via Telegram/Phone call.
  * *P2 (High):* "Sentry detected a new unhandled React TypeError on the Checkout Page". $\rightarrow$ **Action:** Creates a Jira/Linear ticket and alerts the Engineering Slack/Discord channel.
  * *P3 (Warning):* "API latency for `/api/products` exceeded 800ms". $\rightarrow$ **Action:** Logs to the Operations Command Center dashboard for review.

### 🛡️ 4. Security & Privacy in Logging (Crucial for GCC/PDPL)
Because you are handling financial and PII data, your logging system must not become a security liability.
* **The PII Scrubber:** Implement a `structlog` processor that uses Regex to automatically mask sensitive data *before* it is written to the log stream.
  * Credit Card numbers $\rightarrow$ `****-****-****-1234`
  * Passwords $\rightarrow$ `[REDACTED]`
  * Bearer Tokens $\rightarrow$ `[REDACTED]`
* **Data Residency:** Ensure the Loki/Sentry servers are hosted in a region that complies with your target market's data residency laws (e.g., hosting the logging infrastructure in Oman or KSA if PDPL requires strict localization of debug data).
