# Phase 1 — Create scripts/audit_schemas.py

This script produces `_generated/DATABASE_INVENTORY.md`.

## Requirements

- Python 3.13+
- Uses `sqlalchemy` async engine with `asyncpg` (already a dependency)
- Reads `DATABASE_URL_DIRECT` from environment. If unset, exits 1 with message
  `"DATABASE_URL_DIRECT must be set"`.
- Refuses to run against a host that does not contain `neon.tech`. Prints
  `"Refusing to run against non-Neon host: <host>"` and exits 1.
- All queries are `SELECT` or `information_schema` / `pg_catalog` reads. No writes.
- Imports all SQLAlchemy models from `backend/domains/*/models/` to populate
  `Base.metadata`. Uses a package walk that imports every `models` submodule under
  `backend/domains/`. Catches `ImportError` per module and reports the failed imports
  in the output rather than crashing.
- The import root is `backend/` — the script must `sys.path.insert` the `backend/`
  directory so `from infrastructure.database.base import Base` works.

# Phase 3 — Create scripts/audit_security.py

This script produces `_generated/SECURITY_POSTURE.md`.

## Requirements

- Pure static analysis. No database connection. No environment variables required
  except `GIT_SHA` (falls back to `git rev-parse HEAD`).
- Deterministic output. Sort every list.
- Root directory is the repo root (resolve from `__file__`).

## What it reads

1. `backend/middleware/orchestrator.py` — extract the ordered list of middleware classes
   from the source. Match class names against files in `backend/middleware/`.
2. `backend/modules/*/routers/*.py` — for every function decorated with
   `@router.{get,post,put,delete,patch}`, extract:
   - method
   - path
   - file:line
   - whether the function signature mentions `get_current_user`, `Depends(current_user)`,
     or equivalent auth dependency
   - whether the function body contains `require_feature(` or `require_module(` — extract
     the literal string argument
3. `backend/domains/*/features.py` — all `FEATURES` dict keys.
4. `backend/rbac/roles.py` — all `(module, role) → feature_keys` mappings. Expand
   helper constants where statically resolvable; write `UNVERIFIED` for helpers defined
   outside the file.
5. `backend/rbac/catalog.py` — read the aggregation logic; do not execute it.
6. Run `scripts/audit_secrets.py` as a subprocess and capture its summary line
   (`FINDINGS: N potential secret(s) detected`).

Do not import any application code. All extraction is AST-based or regex-based on
source files. This keeps the script independent of runtime configuration.

# Phase 5 — CI integration

Create `.github/workflows/inventory.yml`.

```yaml
name: Inventory Drift

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  drift-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.13"

      - name: Install dependencies
        run: |
          cd backend
          pip install uv
          uv sync

      - name: Regenerate DATABASE_INVENTORY.md
        env:
          DATABASE_URL_DIRECT: ${{ secrets.DATABASE_URL_DIRECT }}
        run: python scripts/audit_schemas.py

      - name: Regenerate SECURITY_POSTURE.md
        run: python scripts/audit_security.py

      - name: Check for drift
        run: |
          if ! git diff --exit-code _generated/; then
            echo "::error::Generated inventory has drifted. Run scripts/audit_schemas.py and scripts/audit_security.py locally and commit the results."
            exit 1
          fi
```

Notes:
- This workflow requires a GitHub secret `DATABASE_URL_DIRECT` pointing at a Neon
  branch. If the secret is not set, the `audit_schemas.py` step will fail with
  `"DATABASE_URL_DIRECT must be set"` and the job will fail loudly. That is the
  intended behavior.
- Do not add this job to `ci.yml`. Keep it as its own workflow so it can be skipped
  or allowed to fail independently during the initial rollout.

Verify:

```bash

echo "YAML OK"
```

Commit:
