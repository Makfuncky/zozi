This is the ultimate **Operations Command Center (CEO Dashboard)**. To build a "Single Window Dashboard" that displays 30+ complex, cross-domain metrics without crashing your database or taking 10 seconds to load, we cannot simply write 30 separate database queries on page load. 

We must architect this as a **Hybrid Real-Time & Pre-Aggregated System**. Below is the complete CTO-level blueprint for designing, building, and scaling this Single Window Dashboard.

---

### 🏛️ 1. Dashboard Layout & UI Architecture (The "Single Window")
To enable fast decision-making, the dashboard must be divided into **Four Strategic Zones**, ordered by urgency and impact.

#### Zone 1: The "Heartbeat" (Real-Time Operational Health)
*Top bar, updating live via WebSockets every 5 seconds.*
*   **Today’s Core:** Today's Orders | Today's GMV | Today's Revenue
*   **Live Fleet:** Active Logistic Partners (Company vs. Individual) | Active Shipments | Delayed Orders | Failed Deliveries
*   **Live Platform:** Active Customers (Buying vs. Window Shopping) | Employees Currently Working (Active Sessions) | System Issues (API Error Rate)

#### Zone 2: The Treasury & Cash Command (Financial Truth)
*Powered strictly by the Double-Entry Ledger, not raw order sums.*
*   **Cash Position:** Available Cash (Free to spend) vs. Locked Cash (Held for payouts/refunds).
*   **Liabilities:** VAT Liability (Owed to Gov) | Pending Supplier Payouts | Pending Logistics Payouts.
*   **Friction:** Refunds Processed Today | Active Financial Disputes.

#### Zone 3: The Growth & Trend Engine (Strategic Analytics)
*Pre-aggregated time-series charts.*
*   **Revenue Trend:** 30-day rolling GMV vs. Net Revenue.
*   **Market Heatmap:** Country-wise Sales (Map visualization).
*   **Category & Product Trends:** Top 5 surging categories, Top 10 trending products.
*   **Customer Intent:** "Most Searched Keywords" (crucial for identifying missing inventory).

#### Zone 4: The Demographics & Ecosystem (Platform Health)
*Deep-dive statistics.*
*   **User Segregation:** Total vs. Active counts for Customers, Suppliers, Employees, and Logistics.
*   **Supplier Health:** Active Suppliers vs. Suppliers with "Issues" (KYC failed, high return rates).
*   **Demographics:** Gender segregation of customer base.
*   **Activity Feed:** A scrolling ticker of critical events (e.g., "New Supplier Registered in KSA", "Country Head approved Payout Batch #402").

---

### ⚙️ 2. Backend Data Aggregation Strategy
If you query the `orders`, `users`, and `shipments` tables directly for all these metrics, the dashboard will timeout. We must implement a **Three-Tier Data Strategy**:

#### Tier 1: Real-Time (WebSocket Push)
*Metrics that change by the second and require instant visibility.*
*   **How it works:** When an order is placed, a shipment fails, or a user logs in, the backend publishes an event to Redis Pub/Sub. The dashboard listens via WebSocket and increments the numbers on the screen instantly without reloading.
*   **Metrics:** Today's Orders, Active Users, System Issues, Delayed Orders.

#### Tier 2: Fast Cache (Redis / 5-Minute TTL)
*Metrics that are heavy to calculate but don't need to be down-to-the-second accurate.*
*   **How it works:** A background cron job runs every 5 minutes, calculates the aggregates, and stores the JSON result in Redis. The dashboard simply reads the Redis key (takes < 5ms).
*   **Metrics:** Most Searches, Category Trends, Product Trends, Country-wise Sales, Gender Segregation.

#### Tier 3: The Treasury Ledger (Instant SQL)
*Financial metrics that must be 100% accurate to the cent.*
*   **How it works:** Because we are implementing the **Double-Entry Ledger**, we do *not* sum up orders to find cash. We simply query the `AccountBalance` table for the `1010 Cash Operating`, `2040 VAT Payable`, and `2010 Supplier Payable` accounts.
*   **Metrics:** Available Cash, Locked Cash, VAT Liability, Pending Payouts.

---

### 🗄️ 3. Database Schema Additions Required
To support the specific metrics you requested, the following tables/views must be added or optimized in the database:

1.  **`search_logs` Table:** 
    *   *Purpose:* Tracks "Most Searches by Customer".
    *   *Columns:* `query`, `country_code`, `user_id`, `results_count`, `created_at`.
    *   *Insight:* If "Searches with 0 results" spikes, the procurement team knows exactly what inventory to buy.
2.  **`user_sessions` / Active Tracking:**
    *   *Purpose:* Tracks "Employees Working" and "Window Shopping vs. Purchasing".
    *   *Logic:* A customer is "Window Shopping" if they have an active session, viewed >3 products, but have no cart activity in the last 10 minutes.
3.  **`system_health_events` Table:**
    *   *Purpose:* Tracks "System Issues".
    *   *Integration:* Connects to Sentry or internal error logging. Counts 5xx API responses, database timeouts, and payment gateway failures.
4.  **`supplier_health_scores` (Materialized View):**
    *   *Purpose:* Tracks "Supplier Problems".
    *   *Logic:* Aggregates cancellation rates, return rates, and KYC expiry dates to flag "At-Risk Suppliers".
5.  **`logistics_partner_types`:**
    *   *Purpose:* Segregates "Logistic Company" vs "Logistic Individual Partner" (Gig-economy drivers vs. Fleet companies).

### 🚨 2. The Escalation & Alert Matrix (The "Siren")
Alerts should not just be a list of errors; they must have **timers and routing logic**. If an alert is ignored, it must automatically escalate to a higher role.

*   **Tier 1: Operational Alerts (Country Manager):**

    *   *Action:* Requires a digital "Approve/Block" button directly inside the alert.
*   **Tier 3: Critical System Alerts (Admin / CTO):** 
    *   *Example:* "Payment Gateway API failure rate > 15%" or "Treasury Ledger Imbalance detected."
    *   *Action:* Triggers SMS/Email fallback and flashes red on the Command Center.

### 📊 3. Workforce Telemetry & Employee Performance
You need to see *who* is doing the work and *how well* they are doing it, without leaving the Command Center.

*   **Live "On-Duty" Roster:** A widget showing exactly which Country Managers, Moderators, and Support Agents are currently clocked in and active, segmented by country.
*   **Real-Time Performance Tickers:**
    *   *Support:* Average Ticket Resolution Time (by employee).
    *   *Moderation:* Products Approved vs. Rejected per hour (flags if a moderator is auto-approving without looking).
    *   *Finance:* Payout batches processed today.
*   **The "Bottleneck" Identifier:** An AI-driven widget that highlights where work is stuck. (e.g., *"Warning: 45 Supplier KYC documents are pending review, and only 1 Moderator is currently online in the UAE region."*)

### 🗣️ 4. Contextual "War Room" Chat
Standard chat apps (like Slack) are bad for e-commerce because conversations about "Order #12345" get lost in a sea of messages. The Command Center needs **Entity-Attached Threads**.

*   **Contextual Sidebars:** If the CEO clicks on a specific "Failed Delivery" metric, a side-panel opens showing the live chat between the Logistics Manager and the Support Agent *specifically discussing that delivery batch*.

### ⚖️ 5. Grievances, Compliance & Whistleblowing (The "Safe Box")
In a multi-vendor, multi-country platform, internal and external friction is inevitable. The Command Center must have a secure, highly restricted channel for compliance.

*   **Supplier Grievances against Staff:** If a supplier feels a Country Manager is unfairly rejecting their products or demanding kickbacks, they can file a "Compliance Grievance". ### 🧠 Crucial UX & Architecture Considerations (How to not break the UI)

If you put all of this directly on the main CEO Dashboard, it will cause **cognitive overload**. The screen will be too noisy to read the actual GMV and Revenue trends. 

Here is how you architect it so it remains a "Single Window" without becoming messy:

#### A. The "Command Palette" (Ctrl + K / Cmd + K)
Borrow a feature from modern enterprise tools like Stripe or Shopify. By pressing `Ctrl + K` anywhere in the system, a search bar drops down. 
*   An Admin can type: *"Chat with Oman Logistics"* or *"Show me pending KYC for Saudi"* or *"Broadcast system maintenance"* and instantly execute the action without clicking through 5 menus.

#### B. The "Global Action Drawer"
Instead of cluttering the main dashboard, place a **Collapsible Right-Hand Drawer** on the Command Center screen.
*   **Tab 1: Inbox & Alerts** (Escalations, Approvals needed).
*   **Tab 2: Comms** (Shift notes, Broadcasts, Entity-chats).
*   **Tab 3: Roster** (Who is online, performance metrics).
*   *Behavior:* The drawer stays closed while the CEO is looking at charts, but slides out instantly when an actionable alert chimes or when the user clicks the "Comms" icon.

#### C. Strict Role-Based Visibility (Data Isolation)
*   The **CEO/Global Admin** sees the aggregated "Global Command Center" (All countries, all staff, all alerts).
*   The **Country Head** logs into the *exact same URL*, but the Command Center automatically filters: They only see their country's roster, their country's chat threads, and their country's escalations. They cannot see the UAE's internal chats or performance metrics.

#### D. The "Audit Trail" for Communications
Every notice sent, every alert acknowledged, and every shift-handover note must be written to the `admin_change_audit_logs` (which we already designed in the database schema). If a massive fraud event occurs, the company must be able to look back and prove: *"The alert was sent at 2:00 PM, and Employee X acknowledged it at 2:05 PM but failed to act."*

Building an automated **News & Market Intelligence Aggregator** will solve this. It will continuously fetch, sanitize, categorize, and "flush" (ingest) news from multiple global and regional sources directly into the Zozi ecosystem.

This system will serve two distinct purposes:

Here is the complete CTO-level architectural blueprint for the **Zozi News Ingestion Pipeline**.

---

### 🗄️ 1. Database Schema (The Foundation)
We need two normalized tables to handle multiple sources, deduplication, and country-specific targeting.

#### Table A: `news_sources` (The Feeds)
Tracks where the system is pulling data from.
*   `id` (PK)
*   `name` (e.g., "Reuters Business", "Arab News", "ZATCA Gov Portal", "TechCrunch")
*   `url` (The RSS feed URL or API endpoint)
*   `source_type` (ENUM: `rss`, `api`, `scrape`)
*   `category` (ENUM: `market`, `logistics`, `regulatory`, `ecommerce`, `internal`)
*   `target_audience` (ENUM: `admin_only`, `supplier`, `public`)
*   `fetch_interval_minutes` (e.g., 15, 60, 1440)
*   `is_active` (Boolean)
*   `api_key_required` (Boolean - for premium News APIs)

#### Table B: `news_articles` (The Ingested Content)
The master table for all flushed news.
*   `id` (PK)
*   `source_id` (FK -> `news_sources`)
*   `external_id` (String - The GUID or URL from the source, used for **strict deduplication**)
*   `content_hash` (String - SHA256 hash of the title+url to catch duplicate wire stories from different sources)
*   `title` (String)
*   `summary` (Text)
*   `content` (Text - Full scraped article if needed)
*   `url` (String - Link to original)
*   `image_url` (String)
*   `published_at` (DateTime)
*   `fetched_at` (DateTime)
*   `country_code` (String, Nullable - e.g., "SA" if the news is strictly about Saudi Arabia, else NULL for global)
*   `ai_sentiment` (ENUM: `positive`, `neutral`, `negative`, `critical`)
*   `ai_tags` (JSONB - e.g., `["supply_chain", "red_sea", "shipping"]`)
*   `is_published` (Boolean - Allows admins to hide irrelevant/bad articles before they hit the frontend)

---

### ⚙️ 2. The Ingestion Engine (Backend Architecture)
Fetching external websites on the main API thread will crash your server. We must build an **Asynchronous Background Pipeline**.

#### Step 1: The Fetcher Service (`news_aggregator_service.py`)
*   **RSS Parser:** Use the Python `feedparser` library to read standard RSS/Atom feeds.
*   **API Client:** Use `httpx` to query REST APIs (like NewsAPI.org or GNews.io) using API keys stored securely in the environment.
*   **Web Scraper:** Use `newspaper3k` or `BeautifulSoup` as a fallback to extract the main text and hero image if the RSS feed only provides a short summary.

#### Step 2: The Deduplication & Sanitization Gate
News wires often publish the exact same story. Before saving to the DB:
1.  Check if `external_id` or `content_hash` already exists in the `news_articles` table or Redis cache.
2.  Strip HTML tags, malicious scripts, and tracking pixels from the summary/content.
3.  Normalize dates to UTC.

#### Step 3: The AI Enrichment Layer (The "Zozi" Touch)
Before flushing the article to the database, pass the title and summary through your existing `ai_service.py`:
*   **Entity Extraction:** Does the article mention "ZATCA", "Stripe", "Tap Payments", "Red Sea", or "Oman"? If yes, tag it and map it to the relevant `country_code` or system module.
*   **Sentiment Analysis:** Is this a supply chain crisis (`negative/critical`) or a new market opportunity (`positive`)?
*   **Relevance Scoring:** Score 0-100 on how relevant this is to e-commerce. Discard anything below 40 to keep the Command Center clean.
