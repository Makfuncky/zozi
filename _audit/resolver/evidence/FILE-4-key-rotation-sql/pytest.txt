ITEM 8 — PROOF :lim / :off REMAIN BOUND PARAMETERS
================================================================================
8a. The mechanism, quoted from the patched source:
      key_rotation.py:120      .limit(bindparam("lim"))
      key_rotation.py:121      .offset(bindparam("off"))
      key_rotation.py:125-128  db.execute(select_stmt, {"lim": BATCH_SIZE, "off": offset})

8b. BindParameter objects carried on the Select (sqlalchemy.sql.visitors traversal):
      BindParameter key='lim' value=None -> :lim
      BindParameter key='off' value=None -> :off
    value is None at build time; the real values arrive via execute(params).
    These are genuine binds, not inlined literals.

8c. Compiled SQL per allowlisted table, asyncpg dialect (production driver).

      bound params -> ['lim', 'off']   (asserted identical for all six tables)

8e. Equivalence to the pre-fix statement:
      old text() : ... LIMIT %(lim)s OFFSET %(off)s   (2 bound params)
      new Core   : ... LIMIT $1      OFFSET $2        (2 bound params)
    Identical statement; only the construction method changed.

8f. Why a column name could not simply be bound (the impossibility avoided):
    PostgreSQL bind parameters substitute for VALUES, not for identifiers —
    `SELECT :col FROM t` is rejected by the server, and SQLAlchemy's text() has no
    mechanism to emit an identifier from a bind. The dialect compiler is the only
    correct emitter of identifiers, hence select()/column()/table() with
    quoted_name(..., quote=True) supplying the quoting. This is what the audit's
    prescribed remedy ("use sa.text() with bound parameters") could not have
    achieved, and why contract §5 prescribed Core constructs instead.
