## Over all

### Problem(s)
1. **Float-for-money is systemic**: At least 14 files across finance, orders, payouts, and trading use `float()` for monetary values or declare monetary fields as `float` in Pydantic schemas. This violates Law 19 (no float for money) and causes rounding drift in commission, tax, FX revaluation, and payout calculations.
2. **Return type leak**: Decimal internal types are serialized as `float` in API responses (`_order_to_dict`, supplier finance summary, payout batch serialization). Consumers lose precision; violates Law 89.
3. **Blocking I/O in async return-refund path**: `asyncio.get_event_loop()` + `loop.run_until_complete()` inside an async Tap refund handler freezes the event loop for all concurrent refund requests.
4. **Silent excepts on financial operations**: Tax calculation, FX revaluation, and AML screening all swallow exceptions silently — either proceeding with wrong values or approving prohibited counterparties.
5. **Finance event subscribers are stubs**: The payment.confirmed, payment.refunded, and order.completed events have no active consumers — the order-to-cash chain breaks at the accounting step.
6. **Idempotency key is optional**: PaymentIntentRequest allows `idempotency_key=None`, enabling duplicate payment intents on retry.
7. **Illegal state transition**: `refund_order` allows refund on `cancelled` orders, but the state machine has no `cancelled → refunded` transition.

### Solution(s)
1. Replace all `float()` monetary conversions with `Decimal(str(value))` and `quantize(Decimal("0.01"))`.
2. Serialize Decimal as `str` in all JSON responses; never cast to `float`.
3. Remove `get_event_loop`/`run_until_complete` from async handlers; use `await` directly.
4. Add `logger.warning()` to every silent except in financial code; rollback transactions on journal failures.
5. Implement finance subscribers to post commission accruals, refund reversals, and settlement journals.
6. Make `idempotency_key` required on all payment creation requests.
7. Add `cancelled → refunded` to `allowed_transitions` or reject cancelled orders in `refund_order`.

### Suggestion(s)
1. Add a `Decimal`-only lint rule to `ruff` config to catch float-for-money at CI time.
2. Create a shared `serialize_money(value: Decimal) -> str` helper to enforce consistent serialization.
3. Add integration tests for the order-to-cash chain that verify ledger entries are posted on payment confirmation.
