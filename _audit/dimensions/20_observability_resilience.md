## Over all

### Problem(s)
1. Request ID context is fragmented across three independent ContextVar objects, breaking correlation between middleware, services, and the error tracker.
2. Stale Prometheus config in `monitoring/prometheus/prometheus.yml` has empty `rule_files` and `alertmanagers.targets`; if ever mounted, alerts stop firing.
3. PII redaction function in `logging_middleware.py` is dead code — never called — leaving a gap between the comprehensive field list and actual log output.
4. Prometheus `function_duration_seconds` metric is created anew on every `_record_duration` call and silently fails after the first invocation due to duplicate registration.
5. Sentry error tracker is initialized lazily on first exception; if `sentry_sdk.init` fails, all subsequent exceptions are silently dropped from error tracking.
6. Application log file handler is implemented but never enabled; no log retention policy exists for production stdout logs.
7. DLQ write failures on Valkey outage are silently swallowed, permanently dropping failed events with no alert.
8. No DR runbook exists; recovery during an incident would be ad-hoc.
9. No active-passive failover; single VPS means hardware failure takes down the entire platform.
10. BackupManager exists but is never wired into app lifespan; backups only run via manual trigger or external script.
11. Circuit breakers exist only for payment providers; AI, shipping, SMS, email, threat intel, and voice providers are not wrapped.
12. Restore drill code exists but is never scheduled; backup integrity is unverified until a real disaster.
13. Circuit breaker state transitions are not exported as Prometheus metrics or alerts; ops cannot detect when cascading failure protection activates.
14. Request timeout middleware exists but is not documented in observability dimension coverage.
15. No business-critical metrics for checkout, payment, or order creation flows; only infrastructure metrics are instrumented.
16. Sentry `before_send` does not filter health check endpoints; monitoring tool noise pollutes error tracking.

### Solution(s)
1. Consolidate request_id context into a single ContextVar in `logging_config.py` and update all middleware and services to import from that single source.
2. Remove stale `monitoring/prometheus/prometheus.yml` or align it with the root config; add CI check that `rule_files` is non-empty.
3. Remove dead `redact_pii()` from `logging_middleware.py` or integrate it into the request logging pipeline; expand `PII_PATTERNS` in `logging_config.py` to cover names, addresses, IPs, and SSNs.
4. Move `function_duration_seconds` to module-level in `metrics.py` and remove duplicate metric definitions from `logging_middleware.py`.
5. Initialize `ErrorHandler` at application startup in `main.py` and log its health status to `/health/deps`.
6. Enable `RotatingFileHandler` via `setup_structlog(log_file=...)` in `main.py` and add `LOG_RETENTION_DAYS` to `config.py`.
7. Replace bare `except Exception: pass` in `event_bus.py:_send_to_dlq` with explicit ERROR log and `dlq_write_failure_total` counter increment.
8. Create DR runbook documenting primary?replica failover, backup-restore, RPO/RTO, and escalation contacts.
9. Provision secondary VPS and document DNS/Traefik failover switch procedure.
10. Wire `BackupManager` periodic scheduler into `lifespan.py` startup so backups run at the configured interval.
11. Audit each provider call path and add `get_circuit_breaker(name)` wrapper to uncovered external calls (AI, shipping, SMS, email, threat intel, voice).
12. Register a periodic Celery task that calls `run_restore_drill()` and logs the result to the audit trail.
13. Export circuit breaker state, failure count, and state transitions as Prometheus gauges/counters and create alerts for unexpected opens.
14. Add request timeout middleware to observability dimension coverage and verify metrics capture timeout-triggered 504s.
15. Add business metrics: `checkout_duration_seconds`, `payment_failure_total`, `order_creation_total`, `payout_processing_seconds`.
16. Add `request.path` filter in Sentry `before_send` to drop events originating from health check endpoints.

### Suggestion(s)
1. Add a CI lint rule that verifies `prometheus.yml` `rule_files` matches the alerts directory and is non-empty.
2. Add a test that asserts `get_request_id()` returns the same value set by `RequestIDMiddleware` during a simulated request.
3. Add a test that verifies `_record_duration` does not raise on repeated calls.
4. Add a test that asserts all external HTTP calls go through a shared client factory with a default timeout.
5. Add a test that verifies circuit breaker state transitions are reflected in Prometheus metrics.
6. Add a test that asserts health check requests do not appear in Sentry events.
