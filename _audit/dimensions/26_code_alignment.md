## Overall

### Problem(s)
1. `backend/modules/admin/routers/orders.py` has prefix `/api/v1/admin/orders` but contains ZERO order management endpoints — only campaign/email routes from comms domain. Frontend admin/orders page expects 5 order management endpoints (list, status update, refund, delete, bulk-status) which all return 404.
2. Frontend `shared/src/types.ts` and `ListPage` interface use `data`/`pageSize` while backend `PaginatedResponse` uses `items`/`size`/`pages`. The `pages` field is silently dropped by frontend normalization.
3. Pagination params are inconsistent: some backend endpoints use `size`, others use `page_size`. Frontend `useAdminApi` uses `size` but customer catalog expects `page_size`.
4. Frontend `shared/src/permissions.ts` has a static hardcoded `FEATURE_CATALOG` of 185 strings that can drift from backend's dynamically loaded catalog. Current drift: `accounts.permissions.manage` vs `permissions.manage`.
5. Frontend `cartStore.ts` calls `/cart/items/{id}`, `/cart`, `/cart/sync` but backend exposes cart under `/api/v1/customer/orders/items/{id}`, `/api/v1/customer/orders`, `/api/v1/customer/orders/sync`. `resolveRequestUrl` doesn't rewrite `/cart/` paths.
6. Backend returns RFC 7807 Problem Details `{type, title, status, detail, instance, request_id, timestamp}` but frontend `getErrorMessage` only reads `detail`/`message`/`error`, losing `request_id` for support.
7. Mobile `cartStore.ts` has a different `CartItem` shape (no `line_id`, no `cart_item_id`) and different API paths (`/cart/items`) than web `cartStore.ts`, causing cross-device cart sync issues.
8. Frontend `AdminOrder` type has `total?: number` alias and `payment_status?: string` field not present in backend `Order` model; these will be `undefined` at runtime.
9. `resolveRequestUrl` in `client.ts` only special-cases `/auth/` paths but not `/cart/`, `/admin/`, or other backend prefixes; some frontend code uses absolute paths bypassing resolution entirely.
10. `accounts.py` router uses no prefix with absolute paths like `/api/v1/customer/accounts` while all other routers use prefix + relative paths, creating an inconsistent routing pattern.

### Solution(s)
1. Create proper order management routes under `/api/v1/admin/orders`: GET list (with pagination), GET {id}, PUT {id}/status, POST {id}/refund, DELETE {id}, POST /bulk-status. Move campaign routes to `admin/routers/comms.py`.
2. Align `PaginatedResponse` and `ListPage` shapes: use `{items, total, page, size, pages}` everywhere; update frontend `normalizeListPage` to map `items` → `data`, `size` → `pageSize`, include `pages`.
3. Standardize pagination params: accept both `size` and `page_size` in all backend list endpoints, or standardize frontend to always use `page_size`.
4. Replace static `FEATURE_CATALOG` in frontend with runtime fetch from `/api/v1/rbac/catalog`; use `applyRbacCatalogAtoms` to hydrate.
5. Update `cartStore.ts` to use `/api/v1/customer/orders` paths matching backend; update `resolveRequestUrl` to rewrite `/cart/` → `/api/v1/customer/orders`.
6. Update frontend `getErrorMessage` and `handleApiError` to parse RFC 7807 fields (`request_id`, `type`, `timestamp`) for support and debugging.
7. Extract shared `CartItem` interface and cart API paths to `frontend/shared/src/`; import in both web and mobile stores; align mobile store shape with web.
8. Verify backend returns `payment_status` and `total` fields; if not, remove from frontend `AdminOrder` or add to backend `Order` schema.
9. Expand `resolveRequestUrl` to handle `/cart/` → `/api/v1/customer/orders`, `/admin/` → `/api/v1/admin`, or standardize all frontend calls to use absolute paths.
10. Add `prefix="/api/v1/customer"` to `accounts.py` router and convert all routes to relative paths, matching the pattern of all other routers.

### Suggestion(s)
1. Add a CI test that iterates over all `frontend/web_app/src/app/admin/*/page.tsx` files, extracts API paths, and verifies they exist in the FastAPI route table.
2. Add a type-sync CI check that compares TypeScript interfaces against Pydantic schemas and flags mismatches.
3. Add a mobile-web parity test that compares `frontend/web_app/src/lib/*Store.ts` with `frontend/mobile_app/lib/*Store.ts` for shape and API path consistency.
4. Add a pagination shape test that asserts all backend list endpoints return `PaginatedResponse` with `items, total, page, size, pages`.
5. Create a `scripts/sync-permissions.mjs` that generates `frontend/shared/src/permissions.ts` from the backend RBAC catalog at build time.
