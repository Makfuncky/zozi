# ZOZI Mobile App — Complete Feature & UI/UX Analysis

## Goal
Comprehensive analysis of the entire `frontend/mobile_app` codebase to understand feature implementation patterns and identify UI/UX improvements needed for the Expo/React Native mobile application.

## Constraints & Preferences
- **Hard dependency on `@zozi/shared`** via `file:../shared` symlink — local development only, not publishable to npm without restructuring.
- **Android-emulator-bound API host** (`10.0.2.2:8000`) with no environment-configurable override for native builds beyond `EXPO_PUBLIC_API_URL`.
- **React 19.2** + **React Native 0.83** — very recent, cutting-edge versions; some peer-dependency ranges in `shared` don't strictly cover RN 0.83 (`^0.76.0` max).
- **New Architecture** enabled (`newArchEnabled: true` in app.json).
- **Test environment is Node/JSDOM-based** (not React Native), so tests rely on heavy mocking.

## Key Decisions
- **Expo Router (file-based routing)** with a root `Stack` containing four major branch stacks: `(auth)`, `(tabs)`, `supplier`, `logistics-partner`, plus standalone modals (`checkout`, `wishlist`, `chatbot`).
- **Zustand** as the sole state-management library (6+ stores).
- **`@zozi/shared` as single source of truth** for types, theme tokens, API client factory, i18n, business helpers, and some shared Zustand stores (notifications).
- **SecureStore + in-memory token cache** for auth; bearer-token auth with no CSRF cookie.
- **Country/currency context** injected via React Context at root, persisted cross-session, and sent as `X-Country-Code` header on every request.
- **Batch-debounced backend translation API** (`/translate`) with a 2000-entry in-memory cache for Arabic/English dynamic UI text.
- **Real-time updates** via shared `@shared/realtime` WebSocket helper, consumed by admin dashboard, notifications, tickets, and order tracking.

## Next Steps
- Perform a feature-parity audit against `frontend/web_app` to identify missing screens (e.g., supplier storefront customization, admin user management detail, barcode scanning flows).

- Add skeleton/loading/empty states consistently across list screens that currently show bare `ActivityIndicator` or nothing.
- Extract inline `StyleSheet.create` blocks into shared style helpers to reduce duplication.
- Add integration tests for checkout flow and screen-level navigation scenarios beyond the current unit-test focus.
- Consider splitting `lib/api.ts` into domain modules (auth, products, orders, logistics, supplier, admin) — it is now ~1800 lines.

#### Routing & Navigation
- **Root Stack** (`app/_layout.tsx`): A single `expo-router/Stack` with named branch routes: `(auth)`, `(tabs)`, `checkout`, `wishlist`, `chatbot`, `supplier`, `logistics-partner`.
- **Tab Navigator** (`app/(tabs)/_layout.tsx`): 5 tabs: Home, Shop (hidden from tab bar but routable), Search, Cart, Profile.
- **Supplier Stack**: Purple header (`#7C3AED`). Guards with `useAuthStore` — redirects non-suppliers.
- **Logistics Stack**: Blue header (`#0369a1`). Allows admin, sub_admin, and logistics_partner roles.
- **Auth Stack**: `headerShown: false` for seamless auth flow.
- **`app/index.tsx`**: Simple `<Redirect href="/(tabs)/home" />`.

#### State Management
- **Zustand** (v5) as the only state-management library.
- **Mobile-local stores**: auth, cart, wishlist, theme, locale, currency, recently viewed, search history, notification, background job, effect.
- **Context**: `CountryProvider` wraps the app in root layout.

#### API Communication
- **`lib/api.ts`** is the single API module (~1800 lines).
- Built on `createApiClient` from `@shared/api-core`, which handles token refresh, auth expiry callbacks, and interceptors.
- Token storage: `expo-secure-store` on native, `localStorage` on web, with an **in-memory cache** for the access token.
- Base URL: defaults to `http://10.0.2.2:8000` (Android emulator), overridable via `EXPO_PUBLIC_API_URL`.
- Auto-injects `X-Country-Code` header from persisted country selection.

#### Auth
- **`lib/authStore.ts`** (Zustand): `initialize()`, `login()`, `logout()`, `refresh()`.
- **Social login**: UI shows Google/Facebook capability status fetched from `/auth/oauth/providers`, but the actual social sign-in flow is not implemented in mobile.

- `ActivityIndicator` + `FlatList` + `RefreshControl` + `useCallback` is the standard list pattern
- `Alert.alert` is used for confirmations (delete, cancel order)
- `LinearGradient` is conditionally required with `try/catch` fallback in many screens

### 4. UI/UX Analysis

#### What's Working Well
- **Cohesive dark-first design language** with coral (`#FF5C3A`) brand accent and consistent `surface0/surface1/surface2` layering
- **Animated tab bar** with spring-scaled icons and badge counts is polished
- **Comprehensive role-based navigation** — separate stacks for customer, supplier, admin, logistics partner with distinct header branding
- **Real-time updates** integrated at the store/socket level
- **Multi-currency + multi-language** deeply integrated
- **Checkout flow** is the most elaborate screen, handling multiple payment methods, delivery details validation, tax/VAT breakdowns
- **Supplier product form** includes AI-assisted description/media generation and variant templates
- **Logistics partner scan screen** includes camera barcode scanning, signature pad, and state-machine-driven status action buttons
- **Error boundary**, **global error handler init**, and **toast system** are wired at root layout

#### What Needs Improvement

**Style & Theming**
- **Inline style explosion**: Most screens define 50–200 lines of `StyleSheet.create` locally. `makeStyles` only covers ~15 generic tokens. Significant repetition of `borderWidth: 1`, `borderRadius`, `padding`, `gap` patterns.
- **Hardcoded colors** beyond theme palette: `#FF5C3A`, `#7CFC00`, `#32CD32`, `#f59e0b`, `#ef4444`, `#3b82f6` appear inline in dozens of places.

**Loading & Error States**
- **Inconsistent loading states**: Some screens use `LoadingSpinner`, others use `ActivityIndicator`, some use `Skeleton`, many admin screens show bare `ActivityIndicator` with no skeleton.
- **Inconsistent empty states**: Only a subset of list screens use the `EmptyState` component; others render raw `Text` with hardcoded strings.
- **Error state inconsistency**: `ErrorAlert` is used in checkout; elsewhere errors are either silent `catch {}` blocks or inline `Text` with hardcoded strings.

**Accessibility**
- Most `TouchableOpacity`s lack `accessibilityRole` and `accessibilityLabel`
- `accessibilityHint` rarely used
- No `testID` patterns on most screens
- Color-only status indicators (badges) without text labels
- No `accessibilityState` for busy/disabled buttons
- No `accessibilityLiveRegion` for dynamic updates (cart count, notification count, order status)
- Form inputs often lack explicit `accessibilityLabel`
- No `minimumFontScale` / `maximumFontScale` set on `Text` components

**Other Issues**
- **No pull-to-refresh** on several list screens (admin orders, admin suppliers, supplier orders)
- **Hardcoded text strings**: Some screens use raw strings like `"Are you a supplier?"` instead of the translation system; translation coverage is partial
- **Large single-file components**: `admin/dashboard.tsx` is 1600+ lines, `checkout.tsx` is 1346 lines, `products/index.tsx` is 987 lines
- **`lib/api.ts` is monolithic**: 1800+ lines. Should be split into domain-specific files
- **Navigation type safety**: Many `router.push(... as never)` casts indicate missing route type definitions
- **`Platform.OS === "web"` checks** scattered in `api.ts`, `_layout.tsx`, `currencyStore.ts` suggest web support is secondary
- **`createStyles(theme)` recreates StyleSheet on every render** in many screens — a known RN anti-pattern

### 6. Performance Concerns

- **`Promise.allSettled` on home screen** loads 3 endpoints simultaneously — fine, but no stale-while-revalidate cache; every pull-to-refresh hits the network.
- **`useTranslateTexts`** batch-calls `/translate` on every render cycle where locale is not `en` — screens with 20+ simultaneous translations (e.g., admin dashboard) generate large payloads.
- **No `FlatList` `getItemLayout` / `windowSize` tuning** on long lists. `initialNumToRender` not set in most screens.
- **`useCartStore` fetches full cart on every `addItem`** call (`fetchCart()`), causing redundant re-renders.
- **No image caching strategy** beyond React Native's default; `expo-image` is a dependency but not obviously used for product images.

### 7. Developer Experience

#### Adding a New Screen
1. Create a new file under `app/` (or appropriate subfolder)
2. Export a default React component — Expo Router picks it up automatically
3. Required boilerplate: import `useThemeStore`, `makeStyles`, `createStyles`, define `StyleSheet.create`, handle loading/error/empty states manually
4. **Risk**: Route paths are string literals passed to `router.push` with `as never` casts, bypassing TypeScript's typed routes

#### Routing Structure
- **File-based via Expo Router** with nested Stack + Tab navigators
- **Hidden routes** in tabs use `href: null` to enable nested routing without showing in tab bar
- **Modal routes** (`checkout`, `chatbot`) use `presentation: "modal"` at the root Stack level
- **Route parameters** accessed via `useLocalSearchParams()` — works but lacks type safety

#### Utilities Available
- `lib/api.ts` — centralized API client with domain functions
- `lib/useTranslate.ts` — batch translation hook with caching
- `lib/homeInsights.ts` — category highlight builder
- `lib/productRouteFilters.ts` — URL-param-to-filter-state mapper
- `lib/supplierProductForm.ts` — supplier product form helpers
- `lib/supplierProductAi.ts` — AI description/media helpers
- `lib/adminManagementUtils.ts` — admin list/query helpers
- `lib/supplierShipmentWorkspace.ts` — supplier shipment workspace counts
- `lib/logisticsPayoutInsights.ts` — logistics payout calculations
- `lib/toastStore.ts` — global toast notification system
- `lib/backgroundJobs.ts` + `useBackgroundJobStore` — background job tracking
- `@shared/*` — extensive cross-platform business logic library

#### Testing Setup
- **Jest** with `ts-jest`, `testEnvironment: 'node'`
- **Tests** live in `lib/__tests__/` — unit tests for stores, API helpers
- **Detox** configured for E2E with Android emulator configs
- **Coverage gaps**: No component rendering tests for most screens; no integration tests for checkout flow
- **Testing pain points**: Heavy mocking of React Native modules means tests validate logic but not actual native behavior
